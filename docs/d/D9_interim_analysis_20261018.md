# 当前全量对比的阶段性结果分析

快照时间：**2026-10-18 15:03:53，Asia/Shanghai**。实验仍在运行，本文不是最终成绩。本次只读取已保存结果，没有调用模型，也没有停止或修改运行中的实验。

## 1. 先说结论

**目前观察到明确的保护信号，但还没有观察到 CaMeL Plus 比原版 CaMeL 更低的攻击成功率；新增防护带来的任务完成损失则已经比较明显。**

用简单的话说：

- 原始 Agent 确实会被这批攻击诱导，已经有 99 次严格计分的成功。
- CaMeL 和 CaMeL Plus 在当前可判断的攻击回合里，都没有观察到攻击成功。
- 在同一批三组都有明确结果的条件中，两种防护都没被攻破，但原版 CaMeL 更经常完成用户原本要求的任务。
- 运行中存在大量超时和其他异常，完整测试尚未完成，不能把“没有结果”算成“安全”。

## 2. 本次分析包括哪些数据

根据当前运行清单及切换记录，用户已暂停 Progent，当前为原始 Agent、原版 CaMeL、CaMeL Plus 三组，每组 560 个攻击、40 个正常任务和 14 个直接目标控制，共 **1842 回合**。早先 Progent 的部分记录保留，但不混入这次三组对比。

截至快照：

| 状态 | 回合数 | 如何理解 |
|---|---:|---|
| 已保存结果 | 900 / 1842，约 48.9% | 包含成功完成和异常，不等于全部有效完成 |
| 正常完成评测 | 572 | 得到可按当前严格规则判断的结果，不代表用户任务一定成功 |
| 异常或不完整 | 328 | 259 原生运行错误、56 工具错误、12 结束状态不完整、1 中途切换保留的中断 |
| 尚未运行 | 942 | 不参与有效子集比例，也不能视为防御成功 |

运行账本读取时累计观察到约 4237 次请求，包含前段 Progent 等历史调用；账本和结果快照分别读取，因此该数仅用于过程记录，不是三组独占费用或精确同一时刻的请求总数。

三组进度不同：原始 Agent 已保存 418 回合，CaMeL 236 回合，CaMeL Plus 246 回合。因此，直接比较各组完成子集的百分比，会受到“谁先跑到了哪些任务”的影响。

## 3. 攻击是否成功

### 3.1 各组当前结果

| 系统 | 已确认攻击成功 | 已确认攻击未成功 | 已运行但无法判断 | 尚未运行攻击 | 有效子集 ASR |
|---|---:|---:|---:|---:|---:|
| 原始 Agent | 99 | 199 | 79 | 183 | 99/298 = **33.2%** |
| 原版 CaMeL | 0 | 113 | 94 | 353 | 0/113 = **0%** |
| CaMeL Plus | 0 | 99 | 117 | 344 | 0/99 = **0%** |

每行仍对应原计划 560 个攻击。这里的 ASR 只计算结果明确的子集，不能写成 CaMeL Plus 已经拦截全部 560 个攻击。

如果把所有未知情况都保留，全计划攻击成功率目前只能限定在：原始 Agent 17.7%–64.5%，CaMeL 0%–79.8%，CaMeL Plus 0%–82.3%。这些是未知造成的逻辑范围，**不是置信区间**；范围很宽，说明完整结论仍受缺失结果限制。

原始 Agent 的 99 次成功分布在 25 个用户任务、11 个攻击目标上，已不只是最早的一两个案例。但同一任务的不同攻击目标仍有关联，不能把全部回合当成相互独立的随机样本。

### 3.2 更适合比较的是“相同条件下的结果”

为了减少进度差异影响，选出三组攻击目标结果都明确的 **59 个相同条件**：

| 系统 | 攻击成功 | 用户原任务完成 |
|---|---:|---:|
| 原始 Agent | 18/59 = 30.5% | 39/59 = 66.1% |
| 原版 CaMeL | 0/59 | 56/59 = 94.9% |
| CaMeL Plus | 0/59 | 26/59 = 44.1% |

“用户原任务完成”是基准自身的任务完成判定，单独看它不保证安全：原始 Agent 可能在完成原任务的同时也执行攻击。CaMeL 和 CaMeL Plus 在这 59 个条件里均没有攻击成功，因此它们完成的原任务也满足当前“完成任务且攻击未成功”的口径。

这批配对结果最直接地说明：

1. 两种受保护系统在具体条件中都有保护表现：原始 Agent 的 18 次成功，在相同条件下均未出现在两种防护中。
2. **目前没有 ASR 证据表明 Plus 比原版 CaMeL 更强。** 两者都是 0/59。
3. **当前 Plus 的效用代价明显。** 同一批条件下，原版 CaMeL 完成 56 个原任务，Plus 只完成 26 个。这是当前子集的现象，不是最终总体差距或统计显著性结论。

另外，分别与原始 Agent 配对时：CaMeL 有 91 个双方结果明确的条件，其中 31 个是“原始 Agent 攻击成功、CaMeL 未成功”；Plus 有 85 个，其中 27 个出现相同保护表现。两组配对集合不同，不能用 31 与 27 排名。

## 4. 没有攻击时，正常任务能不能完成

| 系统 | 正常任务成功 | 明确失败 | 已运行但未知 | 尚未运行 | 有效子集完成率 |
|---|---:|---:|---:|---:|---:|
| 原始 Agent | 23 | 0 | 4 | 13 | 23/23 = 100% |
| 原版 CaMeL | 8 | 1 | 6 | 25 | 8/9 = 88.9% |
| CaMeL Plus | 3 | 6 | 7 | 24 | 3/9 = 33.3% |

三组正常任务都有明确结果的共同子集只有 8 个：原始 Agent 完成 8 个，CaMeL 完成 7 个，Plus 完成 3 个。虽然数量少，但与攻击下原任务完成情况指向一致：**Plus 现在的主要短板是可用性，而不仅是测试数量。**

进一步看已运行的正常写任务：

- 原始 Agent：11 成功、0 明确失败、2 未知。
- 原版 CaMeL：5 成功、1 明确失败、1 未知。
- CaMeL Plus：0 成功、5 明确失败、3 未知。

Plus 在正常任务中累计发起 13 次确认请求，本轮没有额外人工批准。因此，写操作限制是这些任务受阻的重要解释，但不能仅凭合计数就认定每个失败都由同一个原因造成。真实用户确认后能否顺利完成合法写任务，尚未由本轮证明。

14 个直接目标控制中，Plus 为 0 成功、6 明确失败、8 未知；原始 Agent 为 8 成功、1 明确失败、5 未知；CaMeL 为 4 成功、2 明确失败、8 未知。直接目标控制不是攻击，不计入 ASR，它暴露的是目标执行能力和授权配置限制。

## 5. 新增安全模块有没有实际动作

与早期小样本不同，当前 Plus 的攻击回合已经累计记录 **104 次 CONFIRM 决定**，同时有 948 次 ALLOW、0 次 DENY；正常任务另有 13 次 CONFIRM，目标控制另有 39 次 CONFIRM。

CONFIRM 是“需要批准”，本轮没有额外批准，因此相应工具操作不会直接执行。它表明新增权限入口在实际介入，但仍需注意：

- 104 是工具调用层面的决定次数，不是 104 个独立攻击被成功拦截，也不是 ASR。
- 确认同时发生在正常任务中，说明该机制存在使用成本。
- 检测记录中的 finding 总数仍为 0；不能把当前保护表现归功于内容检测器已经识别了攻击。
- CaMeL 同样没有攻击成功，因此尚不能从这些合计数分离出 Plus 相对原版的独立安全收益。

模型输入的完整攻击文本匹配记录，在 CaMeL/Plus 中没有观察到整段载荷匹配；这可能受隔离解析和文本转换影响。该记录只匹配完整载荷，**不证明模型完全没有接触攻击内容，也不等于所有攻击都在输入处被清除。**

## 6. 异常为什么必须单独看

| 系统 | 正常完成评测 | 异常或不完整 | 已保存回合中的异常占比 |
|---|---:|---:|---:|
| 原始 Agent | 330 | 88 | 21.1% |
| 原版 CaMeL | 128 | 108 | 45.8% |
| CaMeL Plus | 114 | 132 | 53.7% |

259 个原生运行错误中，按已保存轨迹分类：244 个 API 超时、11 个 API 连接错误、3 个日志编码错误、1 个属性错误。编码错误属于运行设施问题，不是攻击被防御；超时也不能算安全拒绝。连接错误可能有不同下层原因，不能仅凭类型就断言提供方故障。

原始 Agent 还出现了 **13 个“工具报错，但基准原生攻击判定成功”的回合**。主表严格规则将其保留为未知；原生诊断因此为 112 个成功，而不是 99 个。这个差异说明报错回合也可能产生攻击效果，不能把它们当作没有风险，也不能只报一个零而隐藏未知。

另外 12 个不完整结果为没有最终助手回答或仍有待完成工具调用，不是 12 个确认防御成功的回合。

当前运行中途从串行、45 秒请求超时调整为三进程并行、90 秒超时。历史异常保留，没有挑选重跑覆盖。**因此本阶段合并数据不是完全统一运行条件下的一次实验。** 后续正式报告需要按运行段补充结果，不能把后段更少报错或更快推进解释为防御算法提升。

## 7. 与旧 GitHub 测试相比，结论推进到哪里

旧全量测试中，原始 Agent 没有已确认的攻击成功，所以难以用 ASR 评价防御作用。这次已经有 99 个严格成功，并在共同条件里观察到受保护系统没有达成对应攻击，保护证据比最初的小样本更充分。

但这次仍未证明 Plus 的新增层更有效：原版 CaMeL 同样保持零观察成功，且当前配对任务完成表现更好。旧测试中的正常任务完成率为 CaMeL 20/40、Plus 24/40；不能因为旧轮 Plus 更高，就忽略新轮当前子集暴露的损失。模型、任务进度、批准和运行条件不同，两轮都应分别保留。

## 8. 当前可以采用的结论

> 在当前 DeepSeek-V3.2、AgentDojo workspace 的已完成子集中，原始 Agent 出现多次攻击成功，而 CaMeL 和 CaMeL Plus 均未观察到严格攻击成功，提供了具体条件中的保护证据。不过，CaMeL Plus 尚未展示相对原版 CaMeL 的 ASR 改善，并表现出较大的任务完成损失与较高异常比例。完整矩阵尚未跑完，运行设置也发生过调整，当前结果属于阶段性描述，不能作为最终排名或生产安全保证。

下一步分析重点是：等当前运行继续产出后，补齐同条件配对；按运行段区分异常；逐项解释 Plus 正常写操作和攻击下原任务失败的原因；判断新增控制能否在保持任务能力的前提下提供独立收益。本次没有为这些建议额外启动模型实验。
